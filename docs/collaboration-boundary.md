# Collaboration client boundary

DraftMatter's reusable editor/reviewer core is exposed from `src/sharedEditor/index.ts`. The desktop application consumes that same entrypoint for portable document parsing and review markup, while desktop-only adapters stay outside its dependency graph.

## Browser capability contract

The shared surface supports document editing, review, portable import, and clean client-side export. It does not expose local filesystem access, local processes, code execution, Git, or external renderers. Those capabilities are absent imports, not permissions that a browser caller can toggle.

`browserBoundary.test.ts` walks every local import reachable from the shared entrypoint. The build fails if the graph reaches a desktop adapter or references Tauri, filesystem, child-process, network-socket, or generic host-invocation APIs.

The Hocuspocus synchronization client depends on this browser-safe surface. Desktop publishing and explicit local checkpoints call narrow host adapters outside it; receiving a collaboration session never adds a host capability to the browser package. Browser execution and environment controls are visibly disabled as an additional product-level guard.

## Shared state model

`CollaborativeDocument` uses a Yjs text type for the live portable manuscript and keyed Yjs maps for anchors, authors, proposals, threads, and decisions. Anchors use encoded Yjs relative positions so they continue to resolve after concurrent text insertion. Awareness state carries collaborator identity and cursor presence separately from durable updates, so presence is neither checkpointed nor restored as manuscript data.

The rendered editor binding uses `y-prosemirror` over the named `draftmatter:prosemirror` Y.XmlFragment, with collaborative undo/redo and awareness cursor plugins. Presence shape and colors are validated before entering awareness state, and the service independently binds both DraftMatter and ProseMirror presence IDs to the authenticated connection while rejecting malformed cursors and cross-connection client-ID updates. The binding remains inside the browser-safe package and its two-view test exercises actual ProseMirror transactions on independently offline Yjs documents before convergence.

The underlying transport seam exchanges incremental updates, state vectors, and awareness updates without a service dependency, so reconnect and offline convergence run in deterministic local tests. `HocuspocusCollaborationClient` attaches the authenticated WebSocket provider at the browser boundary and accepts a refreshable, memory-held token provider.

The `draftmatter:resources` map carries keyed image bytes and bibliography snapshots so a browser reviewer can read local figures and formatted references without a filesystem or research runtime. Resource schema, paths, media types and size limits are validated before an owner/editor update is accepted; commenters cannot modify these resources. Initial resources are published atomically only when an owner explicitly initializes an empty room. Reopening an older working tree does not replace server resources. The explicit **Share updated figures & references** action publishes reviewed local updates; accepting a new citation also publishes its selected metadata. Ordinary text edits do not reread or retransmit all figure files. Native exports embed the corresponding image bytes; making a local desktop copy also seeds the shared figure files.

Owner checkpoints materialize referenced images and ordinary CSL JSON together with the exact prepared manuscript under the common project-write transaction. The expected hashes were captured before joining, so external local changes cause a conflict rather than an overwrite. Browser owners receive a project ZIP when figures or references accompany the source. The checkpoint explicitly updates the manuscript's bibliography reference to the materialized JSON, retaining other metadata and preserving old bibliography files. A different document cannot be opened into an active room; leave that session first.

The client journals full Yjs state, including review history and resources, in IndexedDB under the service/workspace/project/authenticated-user identity. Reopening merges recovered state before synchronization rather than replacing it with the server's text. A localStorage fallback supports environments without IndexedDB. Storage errors are visible and unsafe pending writes trigger the close warning. Recovery does not bypass the current server role or restore revoked permissions.

Incoming changes are persisted before the server applies or acknowledges them. A storage failure rejects the message without changing the live room, leaving the client able to retry. Candidate validation rejects unresolved Yjs dependencies and delete sets; authorization cannot be postponed until another user's edit integrates them. Realtime traffic has a dedicated bounded burst/rate budget, independently of REST administration quotas, while membership is still checked for each message.

Review decisions are immutable revision-checked records. A decision starts from a Yjs state-vector token; a stale sequential decision is rejected before it is written. If two offline clients decide incompatibly from the same base, both records survive the merge and the derived proposal state becomes `decision-conflict`. Resolving it requires a new decision that names the exact conflicting records and is based on the merged revision. The authenticated transport verifies decision attribution, revision tokens, conflict-resolution references, and the exact proposal conflict component whose statuses may change, so proposal text or status is never silently chosen by last-writer-wins behavior.

## Workspace authorization seam

The framework-independent policy model and managed PostgreSQL workspace service support owner, editor, commenter, and viewer workspace roles plus optional owner-controlled editor/commenter/viewer overrides for an individual project. The effective project role is checked on every HTTP action and again before live updates; changing an override disconnects stale live sessions so the new capability takes effect immediately. Workspace membership remains the project-visibility baseline, and clearing an override restores the workspace role. The service also supports one-use expiring guest invitations, immediate membership revocation, durable per-session rate limits, and an owner-only activity audit. It validates short-lived OIDC access tokens. Browser sign-in uses Authorization Code + S256 PKCE, strict issuer/state/redirect checks, and memory-only rotating tokens. Invitation secrets are stored server-side only as SHA-256 digests and are never written to the audit.

Browser invitation links carry the one-use secret and collaboration service address only in the URL fragment, so neither value enters the initial HTTP request or referrer. DraftMatter removes that fragment from browser history as soon as it is read. If authentication requires a full-page identity-provider redirect, the invitation is retained in origin-scoped session storage for at most fifteen minutes, consumed once on callback, and removed before it is shown for acceptance. Desktop-only origins fall back to the raw one-use token because they cannot produce a portable browser address.

Every project lookup is scoped by workspace membership before the project identifier is resolved. A missing tenant membership, an unknown workspace, and an unknown project all return the same not-found response, preventing project enumeration across tenants. Both the WebSocket and HTTP adapters call `authorizeProject` for the requested capability before loading collaboration state. Only the owner may initialize an empty room from portable source, which permits a one-time import of existing attribution; after initialization, owner and editor updates both preserve immutable history, accept only their verified author ID for new records, and reject schema or undeclared-root mutations.

## Owner-controlled portable checkpoints

Checkpoint serialization is a pure client operation. It normalizes line endings, materializes missing Yjs-relative anchors, sorts keyed authors/proposals/threads/decisions, preserves the complete decision audit, and emits DraftMatter Review Markup without calling Git or any desktop host. An unresolved concurrent decision blocks checkpoint creation. Two converged clients produce identical UTF-8 bytes, and reopening those bytes produces the same checkpoint again.

While a live session is active, ordinary desktop autosave is suspended. The owner must press **Checkpoint to project** to write those exact bytes with the normal expected-hash conflict guard; browser owners receive an explicit portable download. Git remains a separate deliberate action. The managed service also exposes owner-named immutable recovery checkpoints with verified identity attribution, independently of the local working tree.
